# Use a stateless subagent delivery and lifecycle guard

`subagent_guard.py` guards explicit `send_input` delivery envelopes and may add advisory context when the host surfaces a direct non-terminal `wait_agent` result. Current-task guidance and explicit user stop or replacement requests require `interrupt=true`; deliberately after-current-task input requires explicit `interrupt=false`. It does not persist terminal markers or enforce `close_agent` ordering.

**Status:** accepted

**Decision:** nested `functions.exec` calls do not reliably surface `wait_agent` PostToolUse feedback, and session identifiers are not a stable association key across later tool calls. A marker-based close guard therefore denied valid closes while presenting a protection it could not enforce reliably. Each lifecycle call remains a separate model-visible operation: direct where available, or one call per exec program with the structured result returned unchanged. The runtime registers `PreToolUse` with matcher `send_input$` and a stateless `PostToolUse` advisory with matcher `wait_agent$`. New input uses one of three delivery envelopes: `ORCHESTRATOR_GUIDANCE:` with `interrupt=true` for guidance that can affect the current task, `AFTER_CURRENT_TASK:` with explicit `interrupt=false` for deliberately queued next-turn input, or `USER_REQUESTED_INTERRUPT:` with `interrupt=true` after an explicit user stop or replacement request. The guard also accepts the previous `ORCHESTRATOR_CORRECTION: <reason_code>` form as an immediate compatibility alias during upgrades, while new prompts do not emit it. An immediate interrupt redirects the current task so the message is handled now; it does not itself close the agent. Each envelope contains exactly one delivery literal followed by non-empty visible input on the first non-empty line of one `message` or `type: text` item; format, control, separator, or combining characters alone do not count. Unclassified input, mixed carriers, additional text items around a delivery literal, text fields on non-text items, malformed field types, mismatched interrupt values, and misplaced or invisibly wrapped prefixes fail closed. This makes queued delivery an explicit choice rather than the fallback for ordinary guidance, without introducing cross-call state. The runtime does not register outer exec or close calls. When a direct wait event is available, the advisory treats timeout, empty, missing, partial, and unrecognized results as non-terminal without associating state across calls. A top-level wait result is authoritative; when a wrapper provides `structuredContent`, only that field is inspected, so agent-controlled content text cannot suppress the advisory. After any accepted input, the main agent waits for a later explicit terminal entry before closing that target.

**Consequences:** the guard remains stateless and cannot determine whether the main agent classified a message semantically correctly or whether a later terminal result belongs to the intended redirected work. It forces the delivery choice to be explicit and rejects malformed or mismatched envelopes. The compatibility alias preserves staggered updates but keeps one deprecated parser branch until a later breaking release removes it. Guidance authority, user-stop authority, post-input waiting, and close ordering remain main-agent responsibilities and are reviewed as orchestration behavior rather than claimed as Hook-enforced safety.
